# 0009 出機紀錄用 id 查一筆、前台不顯示假資料

- 狀態：採用（取代 [0007](0007-security.md) 的「公開出機紀錄上限 100」那一條）
- 日期：2026-10-18

## 背景

- 出機詳細頁是拿 `/api/public/orders?limit=100` 回來在裡面找，第 101 筆以後的出機頁打不開（找不到就轉回首頁），但 sitemap 列了全部，
  搜尋引擎收錄的網址點進去會跳回首頁。出機紀錄頁（標籤篩選）也只看得到最新 100 筆
- API 讀不到時，前端用 `frontend/src/data/` 的範例出機紀錄、範例推薦配單充數；而且一開始的狀態就是範例資料，每次開頁面都會先閃一下假資料才換成真的。
  客人可能看到不存在的出機案例、不存在的配單和價格
- 沒有照片的出機紀錄，前端拿店裡其他主機的照片（`carouselImages`）補，看起來像那台主機的照片

## 決定

- 新增 `GET /api/public/orders/:id`：出機詳細頁直接查那一筆（一樣拿掉 `serviceFee`），沒有回 404，頁面顯示「找不到這筆出機紀錄」
- `GET /api/public/orders` 的 `limit` 多一個 `all`（全部），出機紀錄頁用它在前端篩選。不做分頁：出機紀錄整份存在 D1 的一列，最多約 1.9MB，
  每筆約 1KB，全部下載還可以接受；標籤篩選是 AND、要全部的標籤，分頁的話要把篩選搬到後端，現在不值得
- 出機紀錄、推薦配單讀不到就說讀不到：首頁那一段不顯示，其他頁寫「暫時載入不了」；一開始的狀態是空的。前端的範例資料（`recentOrders`、`featuredBuilds`）刪掉
- 網站文字、分類、技術文章讀不到時照舊用前端內建的內容：網站文字是店家的固定文案，分類、文章是一般的介紹內容，不是「某台主機賣了多少錢」這種紀錄
- 出機紀錄沒有照片就顯示淺灰底＋主機圖示的空白格（`components/OrderPhoto.tsx`），不拿別台的照片

## 代價

- 出機紀錄頁每次下載全部的出機紀錄，筆數很多時會變慢；到時候要改成後端分頁、篩選，或把出機紀錄拆成自己的資料表
- API 掛掉時首頁會少兩段（推薦配單、近期出機），不像以前「看起來都正常」
